## 1. 確認環境の方針（ブランチ＝ステージング）

- **ディレクトリ分け（`/v2` 等）はやらない。** 本番ドメイン上に公開されるため、検索エンジンにインデックスされる・GA4データが混ざる・ナビやOGPの二重管理になる、というデメリットが大きい。
- **ブランチを切って push すれば Vercel が自動で Preview URL を発行する**（`umanusi-design-git-<branch>-<team>.vercel.app` 形式）。`main` の本番は一切影響を受けない。GitHub に上げても本番には反映されない。
- 手順
  1. `git switch -c renewal/phase1`
  2. 作業・コミット・`git push -u origin renewal/phase1`
  3. GitHub で Draft PR を作成 → Vercel bot が Preview URL をコメント。スマホでも確認可能
  4. 確認OK後に PR をマージ → 本番反映
- **Preview 環境の計測汚染対策**: GA4 と Tawk は `process.env.NEXT_PUBLIC_VERCEL_ENV === 'production'` の時だけ読み込む（開発・Preview では無効化）。Tawk は動作確認したい場面があるので、`NEXT_PUBLIC_ENABLE_CHAT=1` で強制ONできるようにする。
- ローカル確認は従来通り `npm run dev`。

### 2-2. 分かりづらさに関する指摘（設計で解消する）

1. **「アイテム」と「事例」の混同リスク。** 見出しを「なにが作れる？（対応アイテム）」「なにを作った？（制作事例）」のように問いの形で統一し、両ページ冒頭に相互リンクと1行説明を置く。
2. **料金の誤認（Tシャツ¥10,000＝1枚¥10,000）。** 料金セクションを「デザイン制作費」＋「印刷・製造費（実費）」の2カラム図解にし、既存の「印刷代参考料金」（名刺20部¥1,050 等）を右カラムに統合する。単独の「印刷代参考料金」セクションは廃止。
3. **TOP情報過多の再発リスク。** 現TOPの15セクションを10前後に圧縮。「3つの価値」「活用シーン」は独立セクションをやめ、馬主デザイナー紹介・アイテムカードの用途タグに吸収する。
4. **CTA文言の不統一。** 「制作を相談・依頼する」「Contact」が混在。全て **「馬主デザイナーに相談する」** に統一し、補助文「相談だけでもOK／仕様が決まっていなくてもOK」を添える。
5. **「こんな相談ができます」の例文は多すぎると診断UIに見える。** 6件程度をチップ表示にし、各チップはクリックで問い合わせ導線（フォーム or チャット）に繋げる程度に留める。
6. **noteセクションの位置。** 相談CTAより下に置き、回遊の最後に。TOPの必須要素ではないので縮小してよい。
